# Telegram Media Saver Bot — дизайн

Дата: 2026-06-28

## Цель

Telegram-бот, которому пересылаешь сообщения с медиа (фото, видео, музыка,
документы). Бот в пакетном режиме автоматически скачивает их и раскладывает
файлами на сервере, чтобы потом одним махом выкачать по SFTP/rsync — вместо
медленного скачивания по одному файлу из клиента Telegram.

## Ключевые решения

- **Размер файлов:** до 2 ГБ. Достигается за счёт MTProto-библиотеки —
  отдельный локальный Bot API сервер не нужен.
- **Библиотека:** **Kurigram** — активно поддерживаемый форк Pyrogram
  (Pyrogram архивирован 23.12.2024, Telethon — 21.02.2026). API
  Pyrogram-совместимый.
- **Выгрузка:** прямой доступ к каталогу по SFTP/SMB/rsync. Веб-интерфейс,
  отправка ZIP обратно в чат и облачные хранилища — не нужны (YAGNI).
- **Организация файлов:** по пакету. Каждый пакет пересланных сообщений —
  отдельная папка.
- **Граница пакета (гибрид):** пакет закрывается либо по паузе во времени
  (`BATCH_TIMEOUT`, по умолчанию 30 сек без новых файлов), либо по нажатию
  инлайн-кнопки «✅ Завершить пакет».
- **Стек/окружение:** Python + Kurigram, запуск в Docker на VPS пользователя.
- **Доступ:** только владельцу — белый список Telegram user ID.

## Архитектура

Один Python-процесс на Kurigram (MTProto), в Docker-контейнере на VPS. Бот
слушает входящие сообщения, скачивает медиа напрямую (до 2 ГБ), раскладывает по
папкам-пакетам в каталог, смонтированный как Docker volume. Каталог
забирается по SFTP/rsync.

```
Telegram ──forward──▶ Kurigram Bot ──▶ Batch Manager ──▶ /storage/<пакет>/файлы + manifest.json
                          (Docker, volume /storage) ◀── SFTP/rsync ── пользователь
```

## Компоненты

Каждый — отдельный модуль с одной ответственностью.

### `config.py`
Читает конфигурацию из переменных окружения:
- `API_ID`, `API_HASH` — с my.telegram.org (нужны для MTProto).
- `BOT_TOKEN` — токен бота от @BotFather.
- `ALLOWED_USER_IDS` — белый список Telegram ID (через запятую). Только эти
  пользователи могут пользоваться ботом.
- `STORAGE_DIR` — базовый каталог для файлов (внутри контейнера; монтируется
  как volume).
- `BATCH_TIMEOUT` — пауза в секундах для авто-закрытия пакета (по умолч. 30).

Валидирует обязательные значения на старте; при отсутствии — падает с понятной
ошибкой.

### `bot.py`
Точка входа. Создаёт Kurigram-клиент, регистрирует хендлеры
(медиа-сообщения, callback кнопки «Завершить», команды), проверяет отправителя
по белому списку (чужих молча игнорирует). Связывает хендлеры с Batch Manager.

### `batch_manager.py`
Держит «активный пакет» для пользователя. Отвечает за всю логику границ пакета:
- создание нового пакета при первом файле, когда активного нет;
- сброс таймера авто-паузы при каждом новом файле;
- закрытие пакета по таймеру или по кнопке «Завершить»;
- финализацию (итоговое сообщение).

Логика изолирована от Kurigram (взаимодействие через интерфейсы/коллбэки),
чтобы её можно было тестировать с моками.

### `downloader.py`
Скачивает медиа из сообщения в папку текущего пакета. Выбирает имя файла
(исходное, если есть; иначе `<тип>_<дата>_<msg_id>`), санитизирует небезопасные
символы, разрешает коллизии имён добавлением суффикса (`name.mp4`,
`name (2).mp4`). При сбое скачивания — повтор и пометка ошибки (без падения
всего пакета).

### `storage.py`
Определяет структуру каталога и пишет `manifest.json` в папку пакета.
Манифест пишется инкрементально (после каждого файла), содержит по каждому
файлу: исходное имя, итоговое имя на диске, тип, размер, дату, подпись
(caption), id сообщения.

## Поток данных

1. Пользователь пересылает файл(ы) → хендлер ловит сообщение → проверка белого
   списка.
2. Нет активного пакета → создаётся: папка `STORAGE_DIR/<YYYY-MM-DD_HH-MM-SS>/`.
   Бот отправляет одно сообщение-статус с инлайн-кнопкой «✅ Завершить пакет».
3. Каждый файл скачивается в папку, дописывается в `manifest.json`, счётчик в
   статусе обновляется редактированием того же сообщения
   («Сохранено: 7 файлов, 340 МБ»).
4. Граница пакета (гибрид): пауза `BATCH_TIMEOUT` без новых файлов **или**
   нажатие кнопки → пакет финализируется. Бот шлёт итог: путь к папке, число
   файлов, суммарный размер, число ошибок (если были).

## Обработка ошибок и крайние случаи

- **Большие файлы:** качаются последовательно; при сбое — повтор и пометка в
  итоге, остальной пакет не страдает.
- **Альбомы (`media_group_id`):** естественно попадают в один пакет.
- **Коллизии имён / небезопасные символы:** санитизация + числовой суффикс.
- **Текст без медиа:** игнорируется (опционально — короткая подсказка).
- **Рестарт бота посреди пакета:** `manifest.json` и файлы уже на диске →
  потерь нет; незакрытый пакет финализируется тем, что в нём есть. Состояние
  активного пакета — в памяти (после рестарта новый файл начнёт новый пакет).
- **Чужой пользователь:** молча игнорируется (белый список).

## Тестирование

- Юнит-тесты `batch_manager`: логика таймера, создание/закрытие пакета,
  гибридная граница (таймер vs кнопка) — с замоканным Kurigram.
- Юнит-тесты санитизации имён и разрешения коллизий в `downloader`.
- Юнит-тесты записи/инкрементального обновления `manifest.json` в `storage`.
- Опционально — один интеграционный прогон на тестовом боте с реальными
  файлами.

## Развёртывание

- `Dockerfile` — образ с Python и Kurigram.
- `docker-compose.yml` — сервис бота + volume на `STORAGE_DIR`, переменные
  окружения из `.env`.
- `.env.example` — шаблон со всеми переменными.
- README с шагами: получить `API_ID`/`API_HASH`, токен у @BotFather, прописать
  свой Telegram ID в белый список, поднять `docker compose up -d`, забирать
  файлы по SFTP/rsync из смонтированного каталога.

## Вне области (YAGNI)

- Веб-интерфейс и листинг файлов через браузер.
- Отправка ZIP-архивов обратно в чат.
- Облачные хранилища (S3 и т.п.).
- Многопользовательский режим / квоты.
